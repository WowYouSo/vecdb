# Разбор кода по файлам и блокам

Читать в этом порядке: `flat.py`, `kmeans.py`, `ivf.py`, `wal.py`, `db.py`. На всё уйдёт минут 40.
После каждого файла попробуй пересказать его вслух в двух предложениях: это и есть текст для видео.

## vecdb/flat.py (точный поиск, 40 строк)

- **`squared_norms(X)`**: считает `||x||²` для каждой строки через `einsum`. Вызывается один раз на вектор,
  потом переиспользуется во всех запросах.
- **`flat_scan(X, norms, q, alive)`**: расстояние от запроса до каждой строки.
  Формула `||x-q||² = ||x||² - 2·x·q + ||q||²`. Последнее слагаемое одинаково для всех строк, для
  ранжирования оно не нужно. Остаётся одно умножение матрицы на вектор (`X @ q`), его делает BLAS.
  Операции `*=` и `+=` на месте, чтобы не создавать лишние массивы. Мёртвым строкам ставим `+inf`.
- **`topk(dist, k)`**: `argpartition` находит k наименьших за O(n), сортируем только их.
  В конце отбрасываем `inf`, то есть удалённые строки.

Почему так: наивное `((X - q)**2).sum(1)` создаёт временный массив размером с базу. Именно из-за этого
у проекта m2vdb точный поиск на том же ноутбуке занимает 200 мс.

## vecdb/kmeans.py (кластеризация, 45 строк)

- **`assign(V, C, cnorms)`**: для каждого вектора номер ближайшего центроида. Та же формула, но матрица на
  матрицу (`V @ C.T`). Считаем кусками, чтобы таблица расстояний занимала около 256 МБ, а не 16 ГБ.
- **`kmeans(V, k, iters, seed)`**: алгоритм Ллойда.
  1. Начальные центроиды: k случайных разных точек.
  2. `assign` раскладывает точки по центроидам.
  3. Пересчёт центроидов без цикла по кластерам: сортируем строки по номеру кластера (`argsort`), и
     `np.add.reduceat` суммирует каждую подряд идущую группу.
  4. Пустой кластер получает случайную точку.
  Итераций фиксированное число (10): центроидам достаточно быть примерно правильными.

## vecdb/ivf.py (индекс, 100 строк)

- **Раскладка.** Все векторы лежат одним массивом `vecs`, отсортированным по номеру списка.
  `offsets[c]` и `offsets[c+1]` дают границы списка `c`. Список это срез, без копирования.
- **`build`**: берёт выборку (64 вектора на список), учит k-means, потом `assign` для всех векторов и
  `from_assignment`.
- **`from_assignment`**: стабильная сортировка по номеру списка, `bincount` даёт размеры, `cumsum` даёт
  `offsets`. Заодно считает неравномерность: `nlist · Σ размер² / N²`. Единица значит идеально ровно.
  Возвращает `order`: какая исходная строка оказалась на каком месте. По нему база переставляет id.
- **`list_ids`**: номер списка для каждой строки. Нужен компакции, чтобы не пересчитывать старые строки.
- **`search(q, k, nprobe, alive)`**:
  1. Расстояния до всех центроидов, `argpartition` выбирает `nprobe` ближайших.
  2. Цикл по выбранным спискам (это единственный Python-цикл, его длина `nprobe`). Для каждого списка один
     вызов `np.dot(..., out=...)` пишет расстояния в заранее выделенный буфер `buf`.
  3. `topk` по заполненной части буфера.
  4. `searchsorted` переводит позиции в буфере обратно в номера строк.
  Возвращает ещё и число просмотренных строк: по нему видно, во что обходится запрос.

Ошибка у IVF-Flat одна: настоящий сосед лежит в списке, который не просмотрели. При `nprobe = nlist`
просматривается всё, и ответ совпадает с точным. Это проверяет тест `test_ivf_with_all_lists_is_exact`.

## vecdb/wal.py (журнал, 130 строк)

- **Формат записи**: `длина (4 байта) | CRC32 (4 байта) | тело`. Тело: номер операции `seq`, тип
  (вставка или удаление), число векторов, id, сами векторы.
- **`sync_fd(fd, full)`**: `os.fsync` просит ОС сбросить кэш на диск. На macOS диск может держать данные в
  своём кэше, `F_FULLFSYNC` заставляет сбросить и его.
- **Класс `WAL`, четыре режима** (метод `append`):
  - `buffered`: запись лежит в списке Python, в ОС уходит раз в 64 записи. Падение процесса её теряет.
  - `os`: сразу `write`, без `fsync`. Переживает падение процесса, не переживает отключение питания.
  - `batch`: сразу `write`, `fsync` раз в 64 записи или 50 мс. Это group commit.
  - `always`: `write` и `fsync` до возврата из `append`.
- **`_write`**: цикл на случай, если ОС приняла не все байты за один вызов.
- **`flush` / `sync` / `close`**: `flush` отдаёт буфер ОС, `sync` ещё и вызывает fsync, `close` делает `sync`.
- **`replay(path, dim, apply)`**: читает записи подряд. Останавливается на первой записи, которая короче
  заявленной длины или не сходится по CRC: это хвост, оборванный падением. Возвращает позицию после
  последней целой записи, чтобы обрезать мусор.

## vecdb/db.py (сама база, 430 строк)

**Состояние** (`__init__`):
- запечатанный сегмент: `ivf` (индекс с векторами), `S_ids`, битовая карта `S_alive`;
- дельта-сегмент: `D_vecs`, `D_norms`, `D_ids`, `D_alive`, заполнено `D_n` строк;
- `id2loc`: словарь id → место. Неотрицательное число это строка в запечатанном сегменте, отрицательное
  `-(r+1)` это строка `r` в дельте;
- `seq`: номер последней применённой операции; `gen`: номер поколения чекпойнта.

**`open`** (восстановление):
1. Читает файл `CURRENT`. Если он есть, загружает названный в нём снапшот.
2. Проигрывает журнал. Записи с `seq` не больше, чем в снапшоте, пропускает.
3. Если в конце журнала мусор, обрезает файл.
4. Удаляет файлы, на которые `CURRENT` больше не ссылается, и открывает журнал на дозапись.

**Запись:**
- `insert_many`: сначала `wal.append`, потом `_apply_insert`, потом увеличивает `seq`. Порядок важен:
  в памяти не бывает того, чего нет в журнале.
- `_apply_insert`: дописывает векторы в дельту. Если id уже был, старая версия помечается мёртвой.
- `_reserve_delta`: когда место кончается, ёмкость удваивается.
- `delete`, `_apply_delete`, `_kill`: снимает бит в `alive`, убирает id из словаря. Строка остаётся на месте.

**Чтение** (`search`):
1. Запечатанный сегмент: IVF с `nprobe` списками. Если `exact=True` или `nprobe >= nlist`, то полный
   перебор: он даёт тот же ответ дешевле (маленький планировщик).
2. Дельта: всегда полный перебор.
3. Слияние: для кандидатов (не больше 2k) расстояние пересчитывается напрямую как `||x - q||`,
   потом берутся k лучших. Быстрая формула теряет точность float32, прямая нет.

**Индекс и компакция:**
- `_gather_alive`: собирает живые строки из обоих сегментов.
- `build_index`: k-means с нуля по всем живым векторам, новый запечатанный сегмент, чекпойнт.
- `compact(retrain=False)`: живые строки старого сегмента оставляют свой список, строки дельты получают
  ближайший старый центроид, всё пересортировывается. `retrain=True` учит центроиды заново.
- `_install`: подменяет сегмент, очищает дельту, перестраивает `id2loc`.

**Чекпойнт** (`checkpoint`), порядок шагов защищает от падения посередине:
1. Пишет массивы в `snap-N.tmp/`, делает sync, переименовывает в `snap-N`.
2. Создаёт пустой журнал `wal-N.log`.
3. Атомарно подменяет `CURRENT` через `os.replace`. До этого момента действует старая пара файлов,
   после него новая.
4. Удаляет старый снапшот и старый журнал.

**`_load_snapshot`**: читает массивы, пересчитывает нормы и `id2loc`. Индекс приходит с диска готовым,
k-means при запуске не выполняется.

## bench/ и demo.py

- `common.py`: фиксирует один поток BLAS, загружает SIFT (или синтетику), считает recall.
- `bench_search.py`: наша база, перебор `nlist` и `nprobe`. Время меряется только вокруг `search`.
- `bench_faiss.py`: FAISS на тех же данных. Это чужой код на C++, он нужен как ориентир.
- `bench_writes.py`: вставок в секунду по режимам записи и время восстановления.
- `crash_test.py`: дочерний процесс вставляет и печатает id после возврата `insert`, родитель шлёт
  `SIGKILL`, потом база открывается заново и считает потери.
- `bench_delta.py`: как растёт время запроса с ростом дельты и что возвращает компакция.
- `report.py`: графики и `results/summary.md`.
- `demo.py`: десять шагов подряд для записи видео.
